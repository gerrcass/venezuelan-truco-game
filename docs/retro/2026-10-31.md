# Retro — Truco e' Piedra

**Date:** 2026-10-31
**Scope:** the full build from an empty repo to a deployed 2v2 Venezuelan truco game.

## What worked

- **The ticket graph held.** Seven vertical slices, each demoable, kept the engine, UI, AI and content moving together. The frontier was always obvious.
- **The rules document was the authority.** Every disputed call (flor reservada 5, first-baza flor settlement, prive at 23, no flor-envido subgame) had one written answer. The engine tests read like the rules.
- **The engine was the only test seam.** Table-driven card/scoring tests and whole-hand reducer simulations found the turn-order bug in a raised truco before it reached the browser.
- **One fresh context per ticket.** Implementers did not carry the previous ticket's debugging state; the docs and tickets carried the context instead.
- **The two-axis review paid for itself.** It caught a real information leak (`GameView.seed` could reconstruct the deck) and a ledger that over-reported points at the 24 cap — neither was visible in the E2E happy path.

## Findings and actions

1. **The information boundary needed an explicit rule.** `viewFor` is not just a UI convenience; it is the game's security boundary. The first version exposed the shuffle seed and numeric flor values. **Action:** `CODING_STANDARDS.md` now states that the view must never carry the engine seed, opponent hands, or unrevealed flor/envido values, and every new view field needs a leak test. The tests now assert it.
2. **Evidence can lie.** One early flor screenshot used a rigged state with an impossible duplicate of the vira, which made the UI look wrong when the engine was fine. **Action:** `docs/agents/workflow.md` now says evidence must come from a real seeded deal; the final flor and README screenshots were recaptured from real seeds (`62`, `seed-17`).
3. **One account, not two.** The hand summary briefly had both a legacy "La cuenta" block and the new itemized ledger. **Action:** the ledger is the single source; the match-end summary adds per-team match stats and keeps the final score primary.
4. **CI stopped at unit tests.** The first workflow had no browser proof. **Action:** the CI now runs a Playwright journey against the production build, including a full reparto, the rules school, the language toggle and the 360 px layout.
5. **Keyboard and language were almost complete.** The review found a missing Enter confirmation and hard-coded keycaps. **Action:** Enter confirms the focused primary action, the rules school documents it, and the keycaps are treated as key names rather than translated copy.
6. **Internal English type names vs. the glossary.** The engine still uses `Trick*` identifiers while player-facing English now says **baza**. **Action:** documented in `GLOSSARY.md`; a future wide rename is a separate, mechanical refactor, not a blocker for this ship.

## What I would do differently

- Add the information-boundary test with the first `GameView` field, not after the review.
- Capture evidence from the production build as part of each ticket's acceptance, not as a separate screenshot pass.
- Keep a single `scripts/evidence.mjs` once there is more than one screenshot recipe; the seed-17/seed-62 recipes are currently repeated in the ticket notes.

## Environment changes made

- `AGENTS.md` points at the glossary, rules, ADRs, issue tracker and workflow.
- `CODING_STANDARDS.md` now treats `viewFor` as a boundary and names the leak test.
- CI runs typecheck, lint, unit tests, build and Playwright.
- The rules doc, ADRs and spec are the shared context for every future agent.

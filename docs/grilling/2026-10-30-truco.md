# Grill session — Truco e' Piedra

**Date:** 2026-10-30
**Facilitator:** the agent, with the user's standing instruction: *"move forward, choose what you recommend."*
**Skills used:** `grill-with-docs` → `grilling` + `domain-modeling`

## The objective

> Ship a complete, polished, single-player **2v2 Venezuelan Truco** at **24 piedras**, with the full **Vira / Perico / Perica** hierarchy, **Envido**, **Flor** (including flor reservada), the **Truco → Retruco → Vale nueve → Vale juego** ladder, **Prive**, **quemar**, partner **señas**, three AI personas with table talk, a bilingual ES/EN interface, deterministic seeded play, automated rules tests, an end-to-end browser test, and a live GitHub Pages deployment with a representative screenshot in the README — in one supervised run, with no backend.

The target is deliberately uncomfortable: it is a full card game, not a demo. Every rule in the objective must be playable, testable and visible. "All that jazz" means the weird Venezuelan bits too: the vira flipping the court cards into perico and perica, flor cancelling envido, the prive at 23, and a pana who sends you señas while the comadre narrates your defeat.

Success is not "it compiles". Success is a stranger can open the link, read the rules, play a full partida to 24, and lose to El Catire with dignity.

## Design tree and rounds

The tree was worked in rounds. Each round's answers opened the next frontier. Because the user delegated the decisions, each recommendation below was accepted and recorded; the point of the record is that the assumptions are visible, not silently baked in.

### Round 1 — What game are we actually making?

**Q1. Table format: 1v1 or 2v2?**
Two-player is cheaper, but Venezuelan truco is a partnership game; the señas, the partner AI and half the humor disappear in 1v1.
➡️ **2v2, fixed pairs, you + El Pana vs La Comadre + El Catire.** Seats face each other; play is counterclockwise.

**Q2. Match length?**
Sources play to 12 or 24. Twelve ends too fast to show the betting ladder and the prive.
➡️ **24 piedras, single partida.** Rematch offered at the end.

**Q3. Rules authority?**
Venezuelan truco has table variation. We need one written authority and an explicit list of house decisions.
➡️ **Wikipedia's *Truco venezolano* + Ludoteka's rules as the base**, with every ambiguity resolved in `docs/rules/TRUCO-VENEZOLANO.md` and ADR-0004. The game cites its sources in the rules modal.

**Q4. How much rules fidelity?**
"All that jazz" could mean every regional variant, or the named lances done properly.
➡️ **Full fidelity for the named rules** (vira, perico/perica, envido ladder, flor/reservada, truco ladder, parda, prive, quemar, señas). Flavor-only for **a ley** and **barajo**; no simulated misdeals and no flor-envido betting subgame (both documented). This is the line between rich and unbounded.

### Round 2 — Who is on the other side of the table?

**Q5. Opponents?**
A local hot-seat mode would split the screen and kill the single-player fantasy. Online play is out of scope.
➡️ **Three bots with distinct personas and heuristics.** El Pana is your teammate; La Comadre and El Catire are the rivals.

**Q6. Can the bots cheat?**
Bots that see your hand make every bluff pointless. But bots that only use public information need a real policy.
➡️ **Bots see only their own hand, the public table and the score.** Difficulty comes from aggression and hand evaluation, never hidden information. The engine exposes a `viewFor(seat)` boundary, and the AI is fed that view.

**Q7. How does the pana communicate?**
Partner signals are a core Venezuelan rule and a natural tutorial.
➡️ **One seña per reparto**, drawn from the real gesture vocabulary (perico, perica, espadilla, bastillo, the good sevens, flor). It is a deliberate, limited hint, not a wallhack.

**Q8. How much table talk?**
Silent bots feel like a spreadsheet. Constant quips become noise.
➡️ **Event-driven taunts, one bubble at a time, rate-limited.** ES/EN, persona-specific, never repeats the same line twice in a row. No profanity; the humor is costeño, not crude.

### Round 3 — What does it feel like?

**Q9. Art direction?**
Neon casino is wrong. A generic green table is forgettable.
➡️ **A warm Caracas kitchen-table night:** deep teal felt, cream paper cards, marigold and terracotta accents, wood rim, papelera texture. Custom SVG Spanish deck. No stock card images.

**Q10. Language?**
Spanish-only is authentic but narrows the audience; English-only loses the joke.
➡️ **Spanish-first, fully bilingual ES/EN.** Every string and taunt lives in a typed dictionary. Venezuelan terms stay in Spanish with English glosses where needed.

**Q11. Sound?**
Audio files add weight and licensing questions.
➡️ **Synthesized WebAudio only** (card slap, stone clink, win sting), muted until the first interaction, toggle remembered.

**Q12. Motion?**
Heavy animation is a bug factory.
➡️ **Short, calm, meaningful motion:** deal, card play, trick sweep, stone tally. Respect `prefers-reduced-motion`.

### Round 4 — How is it built and proven?

**Q13. Stack?**
A backend would add accounts, latency and deployment risk for no gameplay benefit.
➡️ **Vite + React + TypeScript, static SPA.** The entire game runs client-side and deploys to GitHub Pages.

**Q14. Engine shape?**
A mutable class hides state transitions and makes AI/test setup painful.
➡️ **Pure reducer over an explicit state machine with a seeded RNG.** Cards, calls, turns and scoring are deterministic and replayable. `viewFor(seat)` is the only information boundary.

**Q15. Testing seam?**
Testing React internals is brittle; testing only the UI is slow.
➡️ **One primary seam: the engine's public API** (`createGame`, `reduce`, `viewFor`, `scoreEnvido`, `scoreFlor`). Unit-test rules exhaustively; reducer-test whole hands; component-test the table; one Playwright journey for the real browser.

**Q16. Definition of done?**
"It works on my machine" is not a shipment.
➡️ **Typecheck + lint + unit tests + production build + Playwright journey green in CI; Pages deployed from `main`; README screenshot taken from the deployed build; no open tickets or PRs.**

### Round 5 — Delivery

**Q17. Where does the work live?**
Direct commits to `main` would make review impossible.
➡️ **One integration branch, one PR using the `pr` skill, a spec issue and tracer-bullet tickets with native blocking edges.** Merge only after review and green checks.

**Q18. What gets cut if the clock runs out?**
The named lances are non-negotiable; garnish is not.
➡️ **Cut order:** extra taunts → avatar art detail → synthesized ambience → match statistics. Never cut: envido, flor, vira, truco ladder, prive, a complete playable partida, deployment.

## Decisions that became ADRs

- **ADR-0001** — 4-player partnerships, 24 piedras.
- **ADR-0002** — pure deterministic engine with a seat-scoped view.
- **ADR-0003** — Vite/React SPA on GitHub Pages.
- **ADR-0004** — house rulings for ambiguous lances.
- **ADR-0005** — Spanish-first bilingual interface.
- **ADR-0006** — fair bots with personas.

## Closed frontier

Every branch is settled: format, ruleset, opponents, information boundary, art, language, audio, motion, stack, engine, tests, delivery, cut order. Nothing is left silently assumed. The implementation can proceed without another decision from the user.
